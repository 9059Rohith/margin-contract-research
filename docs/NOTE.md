# Engineering note

I chose agentic document research for Part C because the same tools that help a model locate clauses also make its evidence trail inspectable. The model can search, read a page, inspect a numbered section, list clauses, and read a bounded block range. Each call is validated before execution, the tools are read-only, and the loop has round and approximate token limits. The hardest design problem was keeping a useful answer from sounding exhaustive after the model had seen only a few retrieved passages. The UI therefore shows measured text coverage, and the server rewrites unsupported absence claims when coverage is partial.

Quote verification happens outside the model. For every proposed quote, I normalize its text and the extracted document text in the same way, collapsing whitespace and normalizing common Unicode punctuation. An offset map tracks each normalized character back to the stored canonical text. A quote earns the Verified label only when it is found in the document it was attributed to; the application computes pages and highlight spans from its own offsets. The model's page numbers and positions are ignored. Unsupported quotes are removed from the evidence list, and a fully unsupported answer is downgraded. This can still fail conservatively when PDF extraction drops text, when DOCX tables or numbering linearize differently from what a person sees, or when a scanned page has no usable text. Very short quotes are rejected to avoid spurious matches. Repeated wording has an occurrence navigator because the first occurrence is not necessarily the intended one.

For long contracts, extraction and FTS5 indexing happen once. The research tools return bounded passages instead of sending a 150-page file to the model. Coverage is the union of passages actually returned to it, not the proportion indexed. This is intentionally conservative: a whole-document search can find a strong positive match, but an unsuccessful narrow search cannot prove absence.

The implementation includes the five tools, validation, live activity events, quote checking, original PDF page highlighting, document comparison, durable extraction leases, and an extractive fallback for installations without an LLM key. The configured live provider passed the supplied single- and multi-document fixtures; other providers and unseen contracts remain unverified. Remaining improvements include OCR for scanned pages, better clause alignment and fallback PDF geometry, an exhaustive map-reduce path, and distributed rate limiting.
